# Thinkific upload bundle — Lyzr University catalog

This bundle maps the Lyzr University catalog onto Thinkific, organized into the catalog's **three
collections** with **every course a numbered leaf folder** (`NN` = course index 1–37). To create a
course: open its folder, select all files, drag into the Content Uploader, done. Coming-soon courses
ship **four placeholder slide PDFs** (see [Placeholder decks](#placeholder-decks)) so the Thinkific
course looks intentional instead of empty; live courses hold their real video + notes.

**Start here: [`_UPLOAD-GUIDE.md`](./_UPLOAD-GUIDE.md)** — the ordered checklist of all 37 courses
with the Thinkific title, categories to tag, status, and files to drag for each.

## What's inside

Each coming-soon leaf folder contains `01 Welcome.pdf` · `02 What You Will Learn.pdf` ·
`03 Course Outline.pdf` · `04 Coming Soon.pdf` (+ a `COMING-SOON.md` dev note where one pre-existed).
Live folders hold the real `NNa …mp4` + `NNb … Notes.pdf` lesson files.

## Coming-soon placeholders

Most courses aren't recorded yet. Their folders hold the four placeholder decks below (and a
`COMING-SOON.md` dev note where one pre-existed) so the full catalog shell — all Tracks, Modules, and
Functions — is mapped and ready: create the Thinkific course with a "Coming soon" marker, then swap in
real lessons when recorded. `04 ADK Tools and Workflows` is fully recorded (lessons 16–19), so it gets
no placeholders.

### Placeholder decks

So a coming-soon Thinkific course isn't an empty shell, each gets **four 16:9 slide PDFs** — i.e. four
lessons (one file = one lesson) — generated by `_generate_placeholders.py`:

| File | Lesson | Contents |
|---|---|---|
| `01 Welcome.pdf` | Welcome | cover · what it is · who it's for · format (lessons/duration/instructor) · coming soon |
| `02 What You Will Learn.pdf` | What you'll learn | outcomes drawn from the course's topic list + skill chips |
| `03 Course Outline.pdf` | Course outline | planned lessons numbered from the topic list + capstone teaser |
| `04 Coming Soon.pdf` | Coming soon | status (no dates) · get notified · live courses you can take now |

- **Source of truth:** `../catalog-demo/catalog-data.json` (the 33 coming-soon courses). Content is
  templated but enriched per course by splitting each `description` into its real topic list; brand
  styling, per-category accent colour + topic-icon watermark come from `../catalog-demo/category-meta.json`
  and `../catalog-demo/lyzr-logo.png`. Rendered to PDF via headless Chrome (`--print-to-pdf`).
- **Skip rule:** folders that already hold a real `.mp4` are skipped (don't bury recorded lessons),
  so `04 ADK Tools and Workflows` gets none. Net: **33 courses × 4 = 132 PDFs.**
- **Disposable:** when a course is recorded, delete its `0N *.pdf` placeholders before uploading the
  real lessons. They're regenerable, so they're **not** tracked in `manifest.csv`.
- Upload them exactly like any course: open the Thinkific course, select the 4 PDFs, drag in → 4 lessons.

## Filename convention (live courses)

`NNa {Title}.mp4` (video) → `NNb {Title} Notes.pdf` (companion notes). `NN` is the SDK curriculum
number; `a` sorts above `b` so each video sits directly above its notes in Thinkific's lesson order.
Keep names short, **no special characters** (the uploader recommends against them — that's why the
on-disk name drops the `SDK Track: NN -` prefix and its colon). Lesson 08 = "File generation";
lesson 10 drops the "?" from "What is RAG?".

> **One file = one lesson.** The Content Uploader makes a separate lesson per file, so the `b` notes
> PDF lands as its **own Download/PDF lesson** right under the `a` video lesson — *not* attached
> inside the video lesson. That pairing-by-sort-order is intentional. If you'd rather the notes be a
> download *inside* the video lesson, that's a manual edit after upload.

## How to upload — per course

1. In Thinkific: **Products → Courses → [the course] → Content**. The uploader is **per-course** —
   it won't read this folder tree to auto-build courses/chapters, so do one course at a time.
2. Add a chapter (or use the default), then **Upload content**.
3. Open the course folder, select all files (`⌘A`), drag into the uploader. One lesson per file,
   auto-named from the filename. Don't leave the tab mid-upload — Thinkific cancels in-flight uploads.
4. After upload you can rename lessons/chapters and drag-reorder or move lessons between chapters
   (8-dot handle) to clean up titles and grouping.

**Uploader limits / accepted types:** video, audio, and PDF only — **video ≤ 2 GB, PDF ≤ 25 MB,
audio ≤ 100 MB, ≤ 50 files per batch**. Our largest MP4 is ~625 MB and each live course is under
50 files, so we're well inside these; just watch the 25 MB cap if a notes PDF ever gets image-heavy.

## Rebuilding

- **Re-render lesson-notes PDFs:** `python3 ../SDK-track/notes/_render_pdfs.py` — writes into the
  correct course folder per lesson module (paths updated for this catalog layout).
- **Regenerate placeholder decks + upload guide:** `python3 _generate_placeholders.py` (idempotent —
  overwrites its own `0N *.pdf` outputs and rewrites `_UPLOAD-GUIDE.md`; `--only <slug>` for one
  course, `--include-partial` to override the skip rule).
- **Rebuild the manifest:** `python3 ../../.agents/skills/descript-to-thinkific/scripts/build_manifest.py .`
  (walks the tree recursively; indexes lesson media only — placeholder decks don't match the `NN[ab]`
  naming and are skipped. `chapter` column = the course folder. `--check` reports drift without writing).
- **Re-run the reorg migration:** `python3 _reorganize_bundle.py` (dry-run) / `--apply` — only needed
  if folders drift back to a legacy layout; normally a one-time operation.
- **Fetch new lessons:** use the `descript-to-thinkific` skill (`fetch_descript.py` → flatten →
  author notes → render → place `NNa` MP4 → rebuild manifest).
